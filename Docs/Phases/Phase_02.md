## 1. الهدف

تحديد سطح الإضافة الكامل وسياسة صلاحياتها، بحيث لا تُضاف صلاحية واحدة بعد هذه المرحلة دون
قرار موثّق.

**المحصّلة:** الإضافة تُثبَّت **بصفر تحذيرات صلاحيات** — لا «قراءة وتغيير جميع بياناتك على
المواقع التي تزورها»، ولا «إدارة تنزيلاتك». مُثبَت من داخل المتصفح لا من الملف.

**ما ليس في النطاق:** الرسائل والتخزين (3) · التوكنز (4) · المكوّنات (5) · الحقن الفعلي (6)
· محتوى النافذة (7).

## 2. البنية

```

public/_locales/{ar,en}/        ← 8 رسائل لكل لغة · ar لغة الأساس
src/shared/
  permission-policy.ts          ← بيانات خالصة: القوائم + الأسباب
  permissions.ts                ← دوال وقت التشغيل (تعيد تصدير السياسة)
  page-paths.ts                 ← بيانات خالصة: مسارات الصفحات
  pages.ts                      ← pageUrl() وقت التشغيل
  restricted.ts                 ← كاشف الصفحات المقيّدة
src/background/index.ts         ← بوّابة الحقن + مستمع الاختصارات
src/pages/{popup,editor,library,settings,onboarding}/index.html
src/offscreen/index.html
scripts/verify-dist.mjs         ← 35 فحصًا على الحزمة والسياسة
scripts/verify-load.mjs         ← تحميل حقيقي + صلاحيات وقت التشغيل
Docs/ADR/permissions.md · Docs/ADR/0005-manual-injection.md
```

### 2.1 لماذا انقسمت الوحدات إلى «بيانات» و«وقت تشغيل»

`manifest.config.ts` يعمل في **Node** أثناء البناء، و`permissions.ts` يستخدم `chrome.*`.
استيراد الثاني من الأول يجرّ واجهات المتصفح إلى مشروع Node ويكسر `typecheck`.

لذلك القوائم في ملفَّي `*-policy.ts` و`page-paths.ts` **بلا أي `chrome.*`**، فيستوردها:

| المستورِد | يستخدمها في |
| --- | --- |
| `manifest.config.ts` | بناء البيان |
| `vite.config.ts` | مدخلات بناء الصفحات |
| `src/shared/permissions.ts` · `pages.ts` | وقت التشغيل |
| `scripts/verify-dist.mjs` | مقارنة البيان المبنيّ بالسياسة |
| `scripts/verify-load.mjs` | مقارنة الصلاحيات الممنوحة بالسياسة |
| `tests/integration/manifest-policy.test.ts` | فحص المصدر قبل البناء |

**النتيجة:** لا يمكن أن تفترق السياسة عن البيان — لأنهما شيء واحد.

## 5. الحالات

### 5.1 حالات منع الحقن — ثمانٍ، لكلٍّ رسالة عربية

| السبب | يُطابق | الرسالة المعروضة |
| --- | --- | --- |
| `browser-internal` | `chrome://` `edge://` `brave://` `about:` `data:` وغير http(s) | لا تعمل الإضافات داخل صفحات المتصفح الداخلية. |
| `extension-page` | `chrome-extension://` `moz-extension://` | لا يمكن الفحص داخل صفحة إضافة أخرى. |
| `web-store` | `chromewebstore.google.com` · `chrome.google.com/webstore` | يمنع المتصفح عمل الإضافات داخل متجر الإضافات. |
| `pdf-viewer` | مسار ينتهي بـ`.pdf` | عارض PDF المدمج لا يقبل الفحص. نزّل الملف وافتحه في محرّر. |
| `view-source` | `view-source:` | صفحة عرض المصدر لا تقبل الفحص. |
| `local-file` | `file://` | الملفات المحلية تحتاج تفعيل «السماح بالوصول إلى روابط الملفات». |
| `devtools` | `devtools://` | صفحات أدوات المطوّر لا تقبل الفحص. |
| `invalid-url` | فارغ · غير صالح · `undefined` | تعذّرت قراءة عنوان هذه الصفحة. |

**دقّة مقصودة:** `chrome.google.com` **مسموح** خارج مسار `/webstore` — النطاق القديم يستضيف
خدمات أخرى، ومنعه كليًا إيجابية كاذبة.

### 5.2 حالات طلب الصلاحية — أربع، بلا تعليق

| الحالة | ما يحدث | النتيجة |
| --- | --- | --- |
| قبول | `request` → `true` | `granted` |
| رفض أو إغلاق الحوار | `request` → `false` (الحالتان لا تُميَّزان في Chrome) | `denied` |
| استدعاء خارج إيماءة | `request` يرمي | `error` |
| غياب واجهة الصلاحيات | لا `chrome.permissions` | `error` |

**أربع حالات، ثلاث نتائج.** `PermissionOutcome` في `src/shared/permissions.ts` ثلاث قيم —
`granted` · `denied` · `error` — والحالتان الأخيرتان تُطويان في `error` واحد. الترويسة كانت
تعدّ النتائج وجدولها يعدّ الحالات؛ صُحّحت إلى عدّ جدولها. التصحيح مسجَّل في §13.

## 6. التدفقات

### 6.1 بوّابة الحقن

```
إيماءة (نقر أيقونة · اختصار)
   → activeTab يُمنح لهذا التبويب فقط
   → checkInjectable(tab.url)
        ├─ injectable ────→ chrome.scripting.executeScript   [المرحلة 6]
        └─ !injectable ───→ popup / restricted + السبب       [المرحلة 7]
```

### 6.2 صلاحية مضيف عند الحاجة

```
ميزة تحتاج البقاء عبر التنقّل (المرجع فوق الصفحة · ورقة cross-origin)
   → عرض السبب  → requestHostPermission([originPatternFor(url)])
        ├─ granted → الميزة كاملة
        └─ denied  → الميزة داخل الجلسة فقط، بلا انهيار
```

### 6.3 التحقّق

```
pnpm build  → typecheck → vite build → verify:dist  (35 فحصًا)
pnpm verify:load → Chrome → Extensions.loadUnpacked → قراءة permissions.getAll()
```

## 11. ما تغيّر عن الخطة، ولماذا

| البند | الخطة | المُنفَّذ | السبب |
| --- | --- | --- | --- |
| `downloads` | صلاحية **دائمة** | **اختيارية** | تُظهر تحذير «إدارة تنزيلاتك» عند التثبيت، ويناقض ذلك معيار المرحلة. والتنزيل من صفحة إضافة ممكن بـ`<a download>` بلا صلاحية. تُطلب عند أول تصدير في المرحلة 19 |

### 11.1 عطلان اكتُشفا — كلاهما كان مخفيًا في المرحلة 1

**1. `--load-extension` يُتجاهَل صمتًا في Chrome 137+.**
فحص `verify:load` في المرحلة 1 كان يمرّ زائفًا: يقبل «أي هدف `service_worker`» فيلتقط إضافة
Chrome مكوّنة (`Google Network Speech`) ويظنّها إضافتنا. **إضافتنا لم تكن محمَّلة أصلًا.**
أُعيدت كتابة الفحص على `Extensions.loadUnpacked` مع استهداف معرّفنا وتحقّق مزدوج من عروبة
الاسم. التصحيح مسجَّل في [`Phase_01.md § 12`](Phase_01.md).

**2. Chrome كان يرفض بياننا.**
كشفه الفحص الجديد فورًا: `Invalid value for 'commands[1].mac': Alt+Command+F`. العطل موجود
منذ المرحلة 1 ولم يُكتشف لأن الفحص لم يكن يحمّل الحزمة. مصدره أن التصميم في Figma يحدّد
`⌥⌘F` بينما Chrome لا يقبل مُعدِّلَين أساسيَّين معًا.

**الدرس المطبَّق:** فحص لا يستطيع أن يفشل ليس فحصًا. كل فحص أُضيف بعدها يحمل تحقّقًا مزدوجًا
يكشف الالتباس، لا مجرّد شرط وجود.
