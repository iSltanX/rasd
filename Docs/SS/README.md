## الملكية ومناطق التعارض

- **يملكه منسّق الإغلاق وحده:** هذا الملفّ خارج الكتلة المشتقّة، و`waves.json`، واللوحة، ووسوم `ss-X/base`، و`AGENTS.md`.
- **ترويسة كل مرحلة** تملكها جلستها عبر `pnpm ss:sync`؛ والتعارض فيها يُحلّ بأخذ أي نسخة ثمّ إعادة المزامنة.
- **ملفّات تتشاركها مراحل الموجة** تُحلّ بالضمّ بترتيب الدمج لا باختيار نسخة: `Docs/Privacy.md` · `package.json` (سكربتاته) ·

- **`ci.yml`** تعدّله المرحلة التي تسمّيه مواصفتها داخل نطاقها (SS3 · SS7)، وإن رفضه مصنّف الأدوات يطبّقه المالك.
- **الحرّاس:** حرّاس كروم عبر `pnpm verify:wave` وحده (قفل الجهاز)؛ وحرّاس Firefox من SS7 عبر `pnpm verify:firefox` بقفلها.
  ولا تُمسّ `scripts/lib/cdp.mjs` ولا `scripts/verify-*.mjs` إلا لسبب وظيفي مكتوب (تصفير السلسلة).
- **صفوف §6 وADR:** «التالي الحرّ» بترتيب الدمج؛ ومن احتاج رقمًا كتبه في سجلّ مرحلته ويُلحقه المنسّق.

## دور: مرحلة ضمن موجة

جلسة Claude Code مستقلّة في worktree مستقلّ على فرع `‹BRANCH›`، بنموذج ‹MODEL›.

1. **تحقّق قبل أي عمل** — كل شرط يُقاس بأمر، وسقوط واحد يوقف الجلسة بطباعة ما سقط:
   - الجلسة في worktree: `git rev-parse --git-dir` غير `git rev-parse --git-common-dir`. وإلا توقّف واطلب جلسة جديدة بخيار worktree.
   - `git fetch origin --tags`، ثمّ الفرع: إن كان `‹BRANCH›` فهو استئناف — تابع من `resume`. وإن كان فرعًا تلقائيًّا أو رأسًا
     منفصلًا بلا تغييرات ولا التزام فوق `origin/main` (`git status --porcelain` فارغ و`git rev-list --count origin/main..HEAD` صفر)
     فأنشئه من أحدث `main`: `git switch -C ‹BRANCH› origin/main`. وإلا توقّف.
   - الوسم `ss-‹WAVE›/base` موجود ومن أسلاف الرأس: `git merge-base --is-ancestor ss-‹WAVE›/base HEAD`.
   - ترويسة `Docs/SS/stages/‹ID›.md` تحمل `wave: ‹WAVE›`، وكل ما في `depends` حالته `done`.
2. **البيئة:** `pnpm install --frozen-lockfile`. **لا `gate:a` في المستهلّ.** وإن سقط `node` أو `pnpm` بـ`_load_nvm`
   (`Docs/ADR/known-issues.md` البند 4) فابدأ الأمر بـ
   `unfunction node npm npx pnpm corepack 2>/dev/null; export PATH="$HOME/.nvm/versions/node/v$(cat .nvmrc)/bin:$PATH";`.
3. **الحالة:** `status: active` في ترويستك وحدها، ثمّ `pnpm ss:sync`.
4. **التنفيذ** داخل النطاق المكتوب في `Docs/SS/stages/‹ID›.md` وحده، بخطوات `AGENTS.md` §3 وفحوص الطبقة الأولى («اقتصاد
   الفحوص»). الدفعات التزامات محلّية على الفرع. التنفيذ في الجلسة نفسها؛ وكيل صغير واحد لمهمّة معزولة إن لزم.
5. **التحقّق مرّة قرب الإغلاق:** أوامر معايير الإغلاق وتُقرأ مخرجاتها، ثمّ `RASD_GATE_BASE=ss-‹WAVE›/base pnpm gate:a`، ثمّ
   `pnpm verify:wave --base ss-‹WAVE›/base --size ‹GATE›`. والمراجعة المستقلّة إن مُسّت المنطقة الحسّاسة. وإن عدّلت حارس كروم أو
   أضفته: `pnpm guards:sync` ويُذكر في التقرير.
6. **التسليم:** سجلّ التنفيذ والمتبقّي و`resume`، والترويسة `delivery: branch` و`commit` آخر التزام عمل (لا `done` — تشترط
   `merged`)، ثمّ `pnpm ss:sync`. ثمّ **تقرير التسليم** بصيغته أدناه تحت سجلّ التنفيذ، ثمّ التزامٌ أخير
   `‹ID›: <النتيجة المحقَّقة> — جاهزة للدمج في الموجة ‹WAVE›`، ثمّ `git push -u origin ‹BRANCH›`. لا PR ولا جولة CI لفرع
   مرحلة. اطبع التقرير وتوقّف.

**ممنوع في هذا الدور:** الدفع إلى `main` أو الدمج فيه · لمس فرع مرحلة أخرى أو ترويستها أو ملفّاتها · تعديل هذا الملفّ أو
`waves.json` أو اللوحة أو `AGENTS.md` أو الوسوم · `gate:a` في المستهلّ أو بعد كل تعديل صغير · تشغيل حارس كروم خارج
`pnpm verify:wave` · انتظار GitHub Actions أو إطلاق جولة · اعتبار خضرة الفرع وحده دليلًا على نجاح التكامل.

## دور: مرحلة منفردة

جلسة في **النسخة الرئيسية** بلا worktree، على `main`، بنموذج ‹MODEL›. المرحلة وحدها في موجتها، فهي مرحلة خطّية ومنسّقة
إغلاقها معًا.

1. **تحقّق:** الجلسة في النسخة الرئيسية؛ `git fetch origin --tags`؛ الشجرة نظيفة والرأس يطابق `origin/main`؛ الوسم
   `ss-‹WAVE›/base` من أسلافه؛ ترويسة `Docs/SS/stages/‹ID›.md` تحمل `wave: ‹WAVE›` واعتمادياتها `done`. ثمّ
   `pnpm install --frozen-lockfile`. لا `gate:a` في المستهلّ.
2. **الحالة:** `status: active` ثمّ `pnpm ss:sync`، في أوّل التزام محلّي.
3. **التنفيذ** بخطوات `AGENTS.md` §3 كاملة، والدفعات التزامات محلّية على `main` لا تُدفع قبل الإغلاق.
4. **الإغلاق:** «دور: إغلاق الموجة» أدناه من خطوته الخامسة بلا دمج: الترويسة `done` و`merged` و`commit` آخر التزام عمل،
   ثمّ البوّابة والوسم واللوحة والدفع.

## دور: إغلاق الموجة

جلسة في **النسخة الرئيسية** بلا worktree، بنموذج ‹MERGE_MODEL›، على `main` نظيف. الموجة ‹WAVE›، والتالية ‹NEXT›.

1. **الشروط:** الشجرة نظيفة؛ `git fetch origin --tags --prune`؛ `git rev-parse HEAD origin/main` متطابقتان؛ الوسم
   `ss-‹WAVE›/base` موجود، ولا وسم `ss-‹NEXT›/base` بعد.
2. **الفروع تُكتشف ولا تُكتب بيد:** `git branch -r --list 'origin/ss/*'`، ولكلٍّ ترويسته
   `git show <الفرع>:Docs/SS/stages/<ID>.md` — `wave: ‹WAVE›` و`status: active` و`delivery: branch` وتقرير التسليم في
   سجلّها، والوسم من أسلافه. كل مرحلة في الموجة لها فرع، ولا فرع لغيرها؛ وإلا توقّف.
3. **الدمج:** `git switch -c integration/ss-‹WAVE› origin/main`، ثمّ لكل فرع بترتيب `order`:
   `git merge --no-ff <الفرع> -m "الموجة ‹WAVE›: دمج <ID> — <العنوان>"`. والتعارض يُحلّ بقواعد «الملكية ومناطق التعارض»
   وبالحدود المعمارية والمواصفة، لا باختيار نسخة. ومواضع الحلّ في المنطقة الحسّاسة تراجعها عدسة واحدة.
4. **لا دمج أسقط غيره:** لكل فرع، ملفّاته `git diff --name-only ss-‹WAVE›/base...<الفرع>`، ثمّ
   `git diff <الفرع> HEAD -- <ملفّاته>` — كل فرق فيه يُنسب إلى مرحلة أخرى دُمجت أو إلى حلّ تعارض مكتوب، وإلا فتغيير سقط.
5. **الحالة قبل البوّابة:** لكل مرحلة `status: done` و`delivery: merged` و`commit` التزام دمجها
   (`git log --merges --grep "دمج <ID>" --format=%h -1`) و`updated` اليوم، ثمّ `pnpm ss:sync`. وإن عُدّل حارس كروم:
   `pnpm guards:sync`. ثمّ التزام واحد: `الموجة ‹WAVE›: <المراحل> — دمج وتثبيت وفتح ‹NEXT›`.
6. **بوّابة الموجة** على الشجرة النظيفة: `pnpm install --frozen-lockfile` إن تغيّر القفل، ثمّ
   `RASD_GATE_BASE=ss-‹WAVE›/base pnpm gate:a`، ثمّ `pnpm verify:wave --base ss-‹WAVE›/base --size ‹GATE›` (ومن SS7:
   `--firefox`). أحمر ⇐ يُصلَح بالتزامٍ على الفرع نفسه، ويُعاد الساقط وما يمسّه الإصلاح والبوّابة مرّة.
7. `git switch main && git merge --ff-only integration/ss-‹WAVE›`.
8. `git tag ss-‹NEXT›/base` على رأس `main` — الإعلان الوحيد بأن ‹NEXT› مفتوحة. والموجة الأخيرة بلا وسم.
9. **التزام اللوحة:** `pnpm ss:sync` ثمّ `الموجة ‹WAVE›: اللوحة — ‹NEXT› مفتوحة`. توثيقٌ خالص بعد الوسم.
10. **الدفع:** `git push --atomic origin main ss-‹NEXT›/base`، ثمّ `git fetch origin --tags` و`git rev-parse HEAD origin/main`
    متطابقتان. والجولة اليدوية إن كانت «مستحقّة» أو «وجوبًا» وسمحت الحصّة: `gh workflow run ci.yml --ref main` — ولا تُنتظر.
11. **التنظيف:** `git push origin --delete <فروع الموجة>`، و`git branch -D integration/ss-‹WAVE›`، ثمّ اطبع `git worktree list`.
12. **البلاغ:** الموجة ‹WAVE› انتهت، و‹NEXT› مفتوحة على `ss-‹NEXT›/base`، وأمر كل مرحلة فيها من اللوحة.

**ممنوع:** `push --force`، وإعادة كتابة التاريخ، و`--no-verify`، ودفع حالةٍ لم تجتز بوّابة الموجة، ووضع وسم على التزام لم
يجتزها، ودمج فرع مرحلة بلا تقرير تسليم.
