# ADR 0005 — الحقن يدوي، لا `content_scripts` تلقائي

**الحالة:** معتمد · **المرحلة:** 2 · **التاريخ:** 2026-08-28

## السياق

الطريقة المعتادة لتشغيل شيفرة داخل الصفحات هي مفتاح `content_scripts` في البيان مع
`matches: ["<all_urls>"]`. المتصفح عندئذ يحقن الشيفرة **في كل صفحة يزورها المستخدم**،
سواء استُخدمت الإضافة أم لا.

بالنسبة لأداة فحص بصري، ذلك يعني أن رصد يعمل داخل صفحة البنك وصندوق البريد ولوحة الإدارة
— بينما المستخدم لم يطلب منه شيئًا.

## القرار

**لا مفتاح `content_scripts` في البيان.** غيابه مقصود، ويُفحص آليًا.

الحقن يتم عبر `chrome.scripting.executeScript` بعد إيماءة صريحة (نقر الأيقونة أو اختصار)،
ويمرّ من بوّابة واحدة:

```
إيماءة → activeTab يُمنح → checkInjectable(url) → executeScript
```

`checkInjectable` في [`src/shared/restricted.ts`](../../src/shared/restricted.ts) يمنع الحقن
في واجهات المتصفح الداخلية وصفحات المتجر وعارض PDF والملفات المحلية، ويُرجع **سببًا**
تعرضه الحالة `popup / restricted` نصًّا مفهومًا لا رسالة خطأ عامة.

## البدائل المرفوضة

| البديل | لماذا رُفض |
| --- | --- |
| `content_scripts` مع `<all_urls>` | حقن دائم في كل صفحة؛ يستلزم صلاحية مضيف دائمة وتحذير التثبيت المخيف |
| `content_scripts` مع `matches` ضيّقة | لا معنى له: رصد أداة تعمل على أي موقع بطلب المستخدم، فلا قائمة مسبقة |
| تسجيل ديناميكي بـ`scripting.registerContentScripts` | يبقى حقنًا دائمًا بعد التسجيل، بنفس المشكلة |

## النتائج

- التثبيت لا يطلب صلاحية مضيف ولا يعرض تحذيرًا — وهو معيار اكتمال المرحلة 2.
- رصد **لا يرى** صفحة لم يُطلب منه فحصها. هذا ادّعاء قابل للإثبات، لا وعد تسويقي.
- المقابل الهندسي: كل مسار يعمل داخل الصفحة يجب أن يتعامل مع «الشيفرة غير محقونة بعد»،
  وأن يكون الحقن المتكرِّر آمنًا. تُبنى هذه الآلية في المرحلة 6.
- الميزات التي تحتاج البقاء عبر إعادة التحميل (المرجع فوق الصفحة) تطلب صلاحية مضيف
  **اختيارية** عند تفعيلها، لا عند التثبيت.
