# ADR 0007 — التوكنز مولَّدة من لقطة، لا من نداء REST

**الحالة:** معتمد · **المرحلة:** 4 · **التاريخ:** 2026-08-28

## السياق

عقد صفحة 32 ينصّ: «متغيّرات Figma هي مصدر الحقيقة… الملفات مولَّدة من هذا المستند».
والخطة تطلب `scripts/tokens-sync.ts` **يقرأ Figma** وينتج `tokens.json`.

لكن **واجهة المتغيّرات في Figma REST متاحة لخطط Enterprise وحدها**. سكربت يعتمد
عليها لن يعمل على هذا الحساب، وسيجعل `pnpm tokens:sync` يفشل بلا مفتاح — ويخالف
معيار الاكتمال: «يعيد إنتاج الملفات الثلاثة بلا فروق».

## القرار

خطوتان منفصلتان:

1. **الالتقاط** — عبر Figma MCP (أو ملحق) يُنتج `src/tokens/figma-snapshot.json`:
   298 متغيّرًا بقيمها لكل وضع، و62 نمط نص، و11 نمط تأثير. اللقطة **مولَّدة ومودَعة**.
2. **التوليد** — `pnpm tokens:sync` يحوّل اللقطة إلى أربعة مخرجات، **بلا شبكة**:

| المخرَج | الموضع | الغرض |
| --- | --- | --- |
| `tokens.json` | `src/tokens/` | صيغة W3C draft بمراجع `{color.signal.300}` |
| `tokens.css` | `public/assets/` | يُخدَم للصفحات وللطبقة داخل الصفحة |
| `tailwind.tokens.js` | `src/tokens/` | مخرَج للمستهلك لا للاستخدام الداخلي |
| `tokens.ts` | `src/tokens/` | أنواع حرفية + `SEMANTIC_HEX` للرسم على Canvas |

`pnpm tokens:sync --check` يُسقط CI عند أي انحراف بين اللقطة والمخرجات.

## النتائج

- **التوليد حتمي وبلا شبكة** — يعمل في CI وعلى أي جهاز، ومُختبَر بايتًا ببايت.
- تحديث التصميم خطوتان لا واحدة: التقاط اللقطة ثم التوليد. الخطوة الأولى تحتاج
  وصولًا إلى Figma، وتقع عند تغيّر النظام لا عند كل بناء.
- اللقطة في المستودع تعني أن تاريخ Git يحمل **تاريخ تغيّر نظام التصميم** نفسه.
- إن أتيحت واجهة REST لاحقًا، تُستبدل خطوة الالتقاط وحدها ويبقى المولّد كما هو.
